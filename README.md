# REDCORE

프리미엄 스트리트웨어 브랜드 REDCORE의 쇼핑몰 웹사이트입니다.
**순수 정적 사이트**로 만들어져 있어 GitHub Pages(또는 다른 정적 호스팅)에
그대로 올리면 서버 설정 없이 동작합니다.

## 바로 확인하기
`index.html`을 브라우저에서 열면 됩니다. (더블클릭해도 되고, 로컬 서버로 열어도 됩니다.)

## GitHub Pages에 올리는 방법
1. 이 폴더 전체(이 README와 `optional-backend-reference` 폴더를 제외한 나머지 전부:
   `index.html` 등 모든 `.html`, `style.css`, `script.js`, `images/`)를
   저장소 루트(또는 `docs/` 등 Pages가 바라보는 경로)에 그대로 올립니다.
2. 저장소 Settings → Pages 에서 배포 브랜치/폴더를 지정합니다.
3. 몇 분 후 발급되는 주소로 접속해 정상 동작을 확인합니다.
4. 기존 파일을 교체할 때는 **폴더 전체를 새 파일로 덮어쓰기**만 하면 됩니다.
   경로는 전부 상대경로(`images/…`, `style.css`, `script.js`)로 되어 있어
   하위 폴더에 배포해도 깨지지 않습니다.

## 이번 작업에서 수정한 것

### 사이트 리뉴얼 (디자인/인터페이스 개편)
- **디자인 새로고침**: 카드·버튼·입력창에 둥근 모서리와 은은한 그림자를 적용해 더 부드럽고 현대적인 느낌으로 바꿨습니다. 브랜드 색상(레드)과 타이포그래피 정체성은 그대로 유지했습니다.
- **헤더 개선**: 현재 보고 있는 메뉴가 빨간 밑줄로 표시되고, 스크롤하면 헤더에 은은한 그림자가 생겨 콘텐츠와 구분됩니다.
- **모바일 메뉴를 서랍(드로어) 방식으로 교체**: 기존엔 헤더 아래로 목록이 펼쳐지는 방식이었는데, 이제 오른쪽에서 슬라이드로 열리고 어두운 배경(백드롭)이 깔리며, 배경을 탭하거나 ESC 키로 닫을 수 있습니다.
- **SHOP 페이지에 실제 검색·필터·정렬 기능 추가**: 상품명 검색창, 카테고리 칩(전체/의류/액세서리 등, 등록된 카테고리에 따라 자동 생성), 정렬(추천순/최신순/낮은 가격순/높은 가격순)이 실제로 동작합니다. 검색 결과가 없을 때는 빈 화면 대신 안내 문구가 표시됩니다.
- **상품 카드에 "빠른 담기" 버튼 추가**: 카드에 마우스를 올리면 상세 페이지에 들어가지 않고 바로 장바구니에 담을 수 있는 버튼이 나타납니다 (클릭해도 상세 페이지로 이동하지 않습니다).
- **브레드크럼(경로 표시) 추가**: SHOP·상품상세 페이지 상단에 "HOME / SHOP / 상품명" 형태로 현재 위치를 보여줍니다.
- **체크아웃 단계 표시**: 장바구니 → 주문 → 완료 3단계를 상단에 표시해 지금 어느 단계인지 한눈에 보입니다.
- **주문서 페이지에 실시간 주문 요약 추가**: 예전엔 입력 폼만 있어서 뭘 사는지 안 보고 결제해야 했는데, 이제 옆에 상품 목록·수량·금액·총액이 실시간으로 보입니다.
- **빈 화면(장바구니 없음, 위시리스트 없음 등)에 아이콘과 안내 버튼 추가**로 다음에 뭘 해야 할지 더 명확하게 만들었습니다.
- 관리자/판매자센터/약관 페이지 등 모든 화면이 같은 디자인 언어(둥근 모서리, 그림자, 여백)를 공유하도록 통일했습니다.
- 리뉴얼 후 기존 4개 테스트 스위트(쇼핑 흐름/약관/판매자센터/재고관리) 전체 재검증 + 새로운 UX 기능 12가지를 자동 테스트로 확인, 22개 페이지 전체를 브라우저로 열어 콘솔 에러 0건, 모바일 가로 스크롤 0건 확인했습니다.

- **로고 색상**: `REDCORE` 전체 글자가 항상 같은 레드 톤으로 표시되도록 CSS의
  상충되는 규칙들을 정리했습니다. (이전에는 뒤쪽 CSS 규칙이 `RED`만 빨강,
  `CORE`는 검정으로 덮어쓰고 있었습니다.)
- **주문 시스템**: GitHub Pages에는 백엔드 서버가 없기 때문에 정상적으로
  동작하지 않던 `/api/orders`, `/api/admin/orders` 호출을 모두 제거했습니다.
  대신 주문 생성·조회는 브라우저 로컬 저장소(localStorage)를 사용해
  주문서 작성 → 주문 완료 → 주문내역까지 끊김 없이 동작합니다.
  실제 카드/간편결제(PG)는 이번 작업에서 임의로 흉내내지 않았으며,
  `optional-backend-reference/`에 실제 서버를 연결할 때 참고할 수 있는
  구조를 남겨두었습니다.
- **관리자 페이지(admin.html)**: 더 이상 존재하지 않는 API 대신, 이 브라우저에
  저장된 주문을 보여주고 상태를 변경할 수 있도록 로컬 저장소 기반으로
  다시 만들었습니다. (여러 사용자의 주문을 한 곳에서 모아 보려면 실제 서버가
  필요하다는 점을 화면에 안내 문구로 표시했습니다.)
- **페이지 전환/애니메이션**: 모든 페이지에 중복으로 들어있던 화면 전환
  스크립트를 `script.js` 한 곳으로 정리했습니다. 페이지 이동 시 흰 화면이
  깜빡이지 않도록 하고, 뒤로가기(bfcache)에서도 정상적으로 보이도록
  처리되어 있습니다.
- **쿠키/개인정보 안내 팝업**: 처음 방문 시 하단에 동의/비동의 배너가
  나타나고, 선택 결과는 저장되어 같은 브라우저에서 다시 뜨지 않습니다.
  안내 문구는 `privacy.html`로 연결됩니다.
- **접근성**: 아이콘만 있는 버튼(위시리스트 ♡, 장바구니, 햄버거 메뉴 등)에
  스크린리더용 라벨(aria-label)을 추가하고, 키보드 포커스가 보이도록
  포커스 스타일을 추가했습니다. 모바일에서 버튼/입력 요소의 터치 영역을
  넓혔습니다.
- **불필요한 파일 정리**: 사용되지 않던 로고 이미지 3개와 홍보 이미지 1개,
  예전 버전의 안내 문서(README/실행용 bat 파일 등)를 삭제했습니다.
- **PRIVACY / TERMS 상세화**: 개인정보처리방침(13개 항목)과 이용약관(21개 조항)을
  국내 전자상거래 표준약관·개인정보 보호법의 일반적인 구성에 맞춰 상세하게
  다시 작성했습니다. 실제 사업자 정보(상호, 대표자, 사업자등록번호, 주소,
  연락처, PG사, 배송업체 등)가 필요한 자리는 <code>[사업자 정보 입력 필요]</code>
  형태의 표시로 남겨두었으며, 문서 상단에 "법률 전문가 검토를 거치지 않은
  초안"이라는 안내 문구를 명시했습니다. CUSTOMER/CONTACT 페이지에도 운영시간·
  이메일·연락처 placeholder를 추가했습니다.
- **REDCORE T-SHIRT 상품 이미지 교체**: 기존에 쓰이던 실사 이미지 2장
  (`tee-main.jpg`, `tee-model.jpg`)을 제거하고, 다른 상품(후디/팬츠/캡)과
  동일한 스타일의 플레이스홀더 이미지(`tee.svg`)로 교체했습니다. 상품명
  "REDCORE T-SHIRT"와 가격 ₩49,000은 그대로 유지되며, SHOP → 상품상세 → CART
  전 구간에서 깨진 이미지 없이 정상 표시되는 것을 확인했습니다.

## 사업 구조 업데이트 — REDCORE는 마켓플레이스가 아니라 "공급받아 파는" 일반 쇼핑몰입니다
Phase 1에서는 "판매자가 직접 입점하는 마켓플레이스" 방향으로 seller-center를
만들었지만, 실제 사업 구조는 **공급처(지인/거래처 등)로부터 상품을 공급받아
REDCORE가 직접 판매**하는 일반 쇼핑몰입니다. 그래서 이번 작업은 admin.html에
**"상품관리(재고·원가·마진)"** 탭을 새로 만들어 이 구조에 맞췄습니다.

**admin.html → 상품관리 탭에서 할 수 있는 것**
- 새 상품 등록: 상품명·카테고리·**공급가**·판매가·재고·이미지·설명을 입력하면
  즉시 SHOP에 노출됩니다 (판매자 승인 절차 없음 — 관리자가 직접 등록하는 구조이므로).
- 기존 4개 기본 상품(T-SHIRT/HOODIE/PANTS/CAP)을 포함한 **모든 상품의 공급가·재고를
  표에서 바로 수정**할 수 있습니다. 공급가를 입력하면 마진(판매가−공급가)과
  마진율이 자동 계산됩니다.
- **공급가는 절대 고객 화면(SHOP/PRODUCT/CART 등)에 표시되지 않습니다.**
  이 부분은 자동 테스트로 실제 HTML에 숫자가 노출되지 않는지 직접 확인했습니다.
- 재고를 입력한 상품은 주문이 들어올 때마다 실제로 차감되며, 0이 되면
  고객 화면에 "SOLD OUT"이 표시되고 구매 버튼이 비활성화됩니다. 재고를
  비워두면 "무제한(재고 관리 안 함)"으로 동작합니다.
- **판매 데이터**: 실제 `orders` 데이터를 기준으로 상품별 판매량·매출·원가·이익을
  자동 계산해 표로 보여줍니다. 공급가를 아직 입력하지 않은 상품은 "원가 미입력"으로
  표시되고 합계에서 제외됩니다 — 숫자를 임의로 지어내지 않습니다.

**⚠️ Phase 1의 seller-center(`seller-signup.html` 등 4개 페이지, admin의
판매자관리/상품검수/수수료관리 탭)는 삭제하지 않고 그대로 남겨뒀습니다.** 지금
사업 구조에는 필요 없지만, 코드는 정상 동작하며 나중에 여러 공급처가 각자
입점하는 진짜 마켓플레이스로 확장하고 싶어지면 그대로 이어서 쓸 수 있습니다.
지금 당장은 무시하셔도 됩니다.

## 삼촌에게 상품을 받아 판매할 때 관리해야 하는 정보
1. 삼촌에게 상품을 받을 때마다 admin.html → 상품관리 탭에서 **공급가**를 정확히
   입력하세요. 입력하지 않으면 그 상품은 마진·이익 계산에서 계속 빠집니다.
2. 재고 수량도 함께 입력해두면, 판매될 때마다 자동으로 줄어들고 소진 시
   자동으로 품절 처리됩니다. (재고 관리를 원치 않으면 비워두면 됩니다.)
3. 판매가를 정할 때 공급가 대비 마진율이 표에 바로 보이니, 가격 책정에 참고하세요.
4. "판매 데이터" 표로 실제로 얼마나 팔렸고 얼마나 남았는지 주기적으로 확인하세요.
5. 이 모든 데이터는 **관리자 화면을 여는 이 브라우저에만** 저장됩니다. 다른
   컴퓨터/브라우저에서 admin.html을 열면 데이터가 보이지 않으니, 실제 운영
   전에는 서버 기반 DB가 필요합니다 (아래 "아직 필요한 외부 서비스" 참고).

HOME, SHOP, 상품 상세(사이즈 선택/이미지 갤러리), 장바구니(수량 변경·삭제·금액
계산), 위시리스트 추가/삭제, 로그인/회원가입(데모), 마이페이지, 주문서 작성 →
주문 완료 → 주문내역, 관리자 화면(로컬 저장 주문 조회/상태 변경), 헤더·푸터의
모든 메뉴 링크, 쿠키 동의 배너, 모바일 반응형 레이아웃, 새로고침 및 뒤로가기,
페이지 전환 애니메이션.

**상품관리(재고·원가·마진) 자동 테스트**: 관리자가 공급가 40,000원 / 판매가
79,000원 / 재고 2개로 새 상품 등록 → SHOP에 즉시 노출 확인 → 공급가가 SHOP·
PRODUCT 페이지 HTML 어디에도 노출되지 않음을 확인 → 2개 주문 → 재고 0 및
SOLD OUT 표시·구매 버튼 비활성화 확인 → 판매 데이터 표에 매출 158,000원/
원가 80,000원/이익 78,000원이 정확히 계산되어 나타나는 것까지 확인. 콘솔
에러 0건.

## 마켓플레이스 확장 — Phase 1 (판매자센터 기본 구조)
REDCORE를 "판매자가 입점해 상품을 파는 마켓플레이스"로 확장하는 대규모 작업을
단계별로 진행 중입니다. 이번 Phase 1에서 만든 것:

**새 페이지**
- `seller-signup.html` — 판매자 입점 신청 (사업자 정보, 정산 계좌, 계정 정보)
- `seller-login.html` — 판매자 로그인 (데모: 승인된 판매자인지만 확인, 실제 비밀번호 검증 없음)
- `seller-dashboard.html` — SELLER CENTER 대시보드 (오늘/이달 판매금액, 주문 상태별 건수, 정산 예정/완료금액)
- `seller-products.html` — 상품 등록/관리 (상품명, 카테고리, 가격/할인가, 재고, 배송/교환/반품 정책 등 전체 입력 항목)

**admin.html 확장 (탭 4개)**
- 주문관리 (기존) — 주문 상태를 12단계(PAYMENT_PENDING ~ REFUNDED)로 확장
- 판매자관리/입점심사 — 대기중인 입점 신청 승인/반려, 승인된 판매자 목록/정지
- 상품검수 — 판매자가 등록한 상품 승인/반려(사유 입력)/숨김. **승인 전에는 SHOP에 노출되지 않음**
- 수수료관리 — 기본 수수료율 + 카테고리별 수수료율 설정, 변경 시 로그 기록

**데이터 구조 (script.js, localStorage 기반)**
`sellerApplications`, `sellers`, `sellerProducts`, `commissionSettings`, `commissionLog` — 향후 실제
서버(DB)로 옮길 때 그대로 스키마 참고가 가능하도록 설계했습니다. 정산 계산은
`calcSettlement(price, qty, sellerId, category)` 함수로 "판매금액 − 수수료 = 정산예정금액"을
계산하며, 수수료율은 판매자별 override → 카테고리 → 기본값 순으로 적용됩니다.

**테스트한 것 (Playwright 자동 테스트)**
판매자 입점 신청 → 승인 전 로그인 차단 확인 → 관리자 승인(계좌번호 마스킹 노출 확인) →
판매자 로그인 → 상품 등록 → 승인 전 SHOP 비노출 확인 → 관리자 상품 승인 → 수수료율 변경 →
정산 계산식 검증 → 대시보드 통계 반영 → 로그아웃 → 재로그인 요구 확인. 전부 PASS, 콘솔 에러 0건.

**⚠️ 이번 Phase 1에서 아직 하지 않은 것 (다음 단계)**
- 구매자 쪽 화면: 여러 판매자 상품을 카테고리로 검색/정렬, 판매자별로 묶인 장바구니, 상품 상세의 판매자 정보 노출, 구매확정 후 리뷰 작성
- 쿠폰/프로모션, 신고 관리, 배너 관리, 공지/약관 관리 UI
- 판매자 약관(21장짜리 TERMS와 별개의 판매자 전용 약관), 배송 조회(송장번호 입력) 화면
- 이 모든 것은 다음 대화에서 이어서 만들 수 있습니다.

**⚠️ 보안 관련 중요 안내**
현재 판매자 로그인은 서버 인증이 아니라 "승인된 판매자 아이디인지"만 브라우저에서 확인하는
데모입니다. 비밀번호 검증, 정산 계좌번호 암호화, 관리자 인증, 접근 로그 등은 전부 실제
서버가 있어야 하는 부분이며, 지금 구조를 실제 운영에 그대로 쓰면 안 됩니다.

- **실제 결제(PG)**: 카드/간편결제를 실제로 승인하려면 결제대행사 계약과
  API 연동이 필요합니다. 이번 버전은 결제를 흉내내지 않으며, 주문서
  제출 시 로컬에 주문 기록만 남깁니다.
- **여러 사용자의 주문을 한 곳에서 관리**하려면 실제 서버·데이터베이스가
  필요합니다. `optional-backend-reference/`에 참고용 Node/Express API
  스타터가 있습니다(정적 사이트 배포에는 포함되지 않아도 됩니다).
- **로그인/회원가입**은 현재 데모용으로 로컬 저장소만 사용합니다. 실제
  회원 시스템을 쓰려면 인증 서버가 필요합니다.
- **문의하기(contact.html)** 폼은 실제 접수 서버가 없어 안내 메시지만
  표시됩니다. 이메일 전송 서비스(예: Formspree 등) 또는 자체 서버 연결이
  필요합니다.
